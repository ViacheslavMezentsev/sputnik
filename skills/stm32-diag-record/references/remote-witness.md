# Удалённый стенд и запись как второй свидетель

Практика проекта платы питания (два профиля, F411 и G474): запись полей по SWD на узле стенда, где
OpenOCD запущен на одноплатном компьютере рядом с платой, и сверка записи с телеметрией прошивки.

## OpenOCD на узле стенда

Отладчик подключён к узлу (Linux-компьютер у платы), запись идёт на ПК разработчика:

```
# на узле: OpenOCD без сброса цели, telnet только на loopback
openocd -f interface/stlink.cfg -c "adapter serial <серийник>" -f target/stm32g4x.cfg \
        -c "bindto 127.0.0.1" -c "telnet_port 4444" -c "init"
# на ПК: туннель и запись в уже запущенный OpenOCD
ssh -N -L 14444:127.0.0.1:4444 <узел>
python scripts/record_diag.py --use-running --host 127.0.0.1 --port 14444 \
       --elf build/app.elf --svd STM32G474.svd --fields fields-dio.toml --seconds 60 --record mcap
```

- OpenOCD на узле не открывайте наружу (`bindto 127.0.0.1`), доступ — только через SSH по ключу.
- Без `--reset`: цель работает, запись не меняет её состояние.
- Один отладчик на несколько плат (платы переставляют): перед записью проверьте, какая плата стоит —
  CRC образа или ревизию из памяти коротким `mdw`, а не по серийнику отладчика.

## Частота опроса через туннель

Каждый цикл — команды telnet через SSH. На практике 9–20 полей GPIO и переменных дают 7–10 Гц
(ODR, IDR, флаги). Отсюда:

- событие короче двух периодов опроса (около 0,2 с) может пропасть: импульсы и быстрые переходы
  сверяйте по числу переходов за окно, а не по каждому фронту;
- «бегущая» индикация с шагом 150 мс видна как переходы, но не каждая позиция; при 10 Гц на 56 переходов
  в телеметрии приходилось 54 в записи;
- поля рядом в памяти (один регистр GPIO, соседние переменные) читаются одной командой — группируйте их.

## Входы с активным низким уровнем

Кнопки и контакты, которые при нажатии замыкают вывод на землю, описываются битом IDR из SVD с
`invert = true`: топик `std_msgs/Bool` тогда равен «нажата». Периферия с `derivedFrom` в SVD (например,
GPIOD = GPIOC у STM32G474) разрешается по регистрам исходной периферии.

```toml
[[field]]
topic = "/diag/dio/btn2"
message = "std_msgs/Bool"
expr = "svd:GPIOB.IDR.IDR4"
invert = true
```

## Сверка с телеметрией прошивки

Запись по SWD — независимый свидетель того, что прошивка публикует сама (ROS, UART, CAN).
Порядок, который сработал:

1. Писать обе записи одновременно: телеметрию на узле (rosbag/mcap), поля — `record_diag.py`.
2. Совместить время по общему событию (смена состояния, нажатие), а не по часам ПК и узла:
   у них может быть сдвиг в доли секунды.
3. Сравнивать долю времени совпадения значений (вне быстрых переходов — 95–100 %) и число переходов
   за окно; длительности нажатий — с допуском в один-два периода опроса.
4. Физическое воздействие (нажатие, замыкание контакта) и подмена значения в памяти — разные уровни
   доказательства: в отчёте указывайте, что именно было на входе.
