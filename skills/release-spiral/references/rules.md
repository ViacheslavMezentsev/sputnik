# Витки, секторы и модель времени

## Витки

- **Рабочая ветка, слитая в линию**, — виток. Если в ветке несколько циклов «изменение → проверка», виток
  заканчивается коммитом проверки (`test…`), за которым идёт не проверка: так ветка `feat-…` с несколькими
  задачами превращается в несколько витков, как при ручном разборе.
- **Прямые коммиты в линию** — витки по перерыву больше суток.
- **Выпуск** — последний виток спирали 1: документы выпуска, слияния в основную ветку и тег.
- **Испытание** (лаборатория, длительная запись) — отдельный виток; добавляется вручную, если события
  испытания не попали в окно одного витка.
- **Спираль 2** — проверки после тега: прогоны, записи и задания, витки по перерыву 12 ч. Её итог — план
  следующего выпуска (замечания, памятка).

Агент называет витки по смыслу («Поправка на диод для ревизии v2.1»), а не по веткам, и при необходимости
склеивает или делит их: правка `turns.json` обязательна.

## Секторы

| Сектор | Дорожки (`lane`) | Коммиты |
| --- | --- | --- |
| план, ТЗ, разбор | План и ТЗ, Разбор и отчёты | `docs(spec)`, `docs(todo)`, `docs(plan)`, исследования |
| изменение | Изменение | `feat`, `fix`, `refactor`, `perf`, `style`, `build`, `revert`; сценарии (`test`) — тоже изменение кода |
| проверка на платах | Локальный стенд, Удалённый стенд, Лаборатория, Ручные испытания, Смена платы, Эмуляция | прогоны, задания, записи |
| CI и выпуск | Локальный CI и скрипты, CI сервера | `ci`, `chore`, CHANGELOG, README выпуска, слияния, теги |

Своя дорожка (например, «Стенд F411») добавляется в `rules.json` → `lanes` с номером сектора.

## Модель времени

| Задача | Минуты | Источник |
| --- | --- | --- |
| Прогон или задание стенда | машинное время + `launch_min` (3) на запуск + `fail_analysis_min` (10) на сбой | `fact` |
| Смена платы на стенде | `board_swap_min` (5) | `est` |
| Локальный CI | длительность из отчёта или `local_ci_min` (5) + запуск | `fact` |
| Конвейер CI сервера | ветка, MR, слияние — 10; тег — 15; образ — 15 | `est` без API |
| Запись испытания | длительность записи + подготовка | `fact` |
| Изменения, ТЗ, документы | занятость: объединение окон 30 мин до каждого коммита, промежутки до 45 мин — работа; делится между планом и изменением по числу коммитов | `est` |

Сумма задач — работа без перерывов и ожидания; календарь занятости — объединение интервалов всех событий
(пересечения один раз). Это разные величины: первая отвечает «сколько стоит выпуск», вторая — «сколько дней
и часов занимал проект».

## Петли

Сбой прогона (`status` не PASS/SKIP) с последующим PASS того же сценария — внутренняя петля витка. На
спирали — красный крест в секторе проверки (не больше восьми на виток), в таблицах — «N зап., M сбоев».
