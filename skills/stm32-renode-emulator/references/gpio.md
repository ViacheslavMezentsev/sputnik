# Кнопки и светодиоды в Renode

В штатном макете (`stm32g4_mock.repl`) порты GPIO — заглушки памяти: запись сохраняется как есть.
`HAL_GPIO_WritePin` пишет в BSRR, поэтому ODR в заглушке не меняется, а «нажатие» записью в IDR прошивка
читает, только пока сама его не перезапишет. Для сценариев с кнопками и индикацией — макет с моделями
портов `assets/stm32g4_gpio.repl` (проверено в Renode 1.17.0).

## Вход: уровень вывода

```
gpioPortB OnGPIO 4 false     # PB4 = 0: кнопка с активным низким уровнем нажата
gpioPortB ReadDoubleWord 0x10 # IDR: бит 4 = 0
gpioPortB OnGPIO 4 true      # отпущена
```

Модель `Miscellaneous.Button`, подключённая к порту, в нашей проверке IDR не меняла — надёжнее `OnGPIO`.

## Выход: светодиод

```
led1: Miscellaneous.LED @ gpioPortC 4
gpioPortC:
    4 -> led1@0
```

`gpioPortC.led1 State` даёт `True`/`False` после записи в BSRR прошивкой (или
`gpioPortC WriteDoubleWord 0x18 0x10` из монитора). Смена индикации во времени — опросом `State` между
`emulation RunFor "0.05"` или журналом LED (`logLevel 0 gpioPortC.led1`).

## Прошивка должна продолжать работать

Если прошивка в режиме эмуляции завершает работу после стартового лога (семихостинг `SYS_EXIT`), до
основного цикла с кнопками и индикацией дело не дойдёт: нужен режим сборки, в котором эмуляция идёт
дальше, а периферия без модели (АЦП, модем) заменена заглушками в коде. Ядро, остановленное на выходе,
видно по неизменному `cpu PC` между шагами `RunFor`.
